# Nova Dark

Theme sources. Build from the repo root with `python scripts/build.py`, or `docker compose run --rm build`; see the root README for everything else.

Every build produces **every variant**. There is no "current" palette or density to switch between.

```
nova-dark/
├── variants.json           THE MATRIX. Declares the axes; the build takes
│                           their cartesian product. Adding a value is one
│                           fragment file plus one line here.
├── config/                 GENERATED, one per palette. Checked in so a colour
│                           change shows up in `git diff` as colours.
├── source/
│   ├── palettes/           WHAT A COLOUR IS. The only files allowed a hex
│   │   ├── _states.scss    literal; the build fails otherwise.
│   │   ├── _nebula.scss
│   │   ├── _graphite.scss
│   │   └── _slate.scss
│   ├── densities/          HOW TIGHTLY IT IS PACKED. Geometry only; a colour
│   │   └── _comfortable.scss   here fails the build. One value today; the
│   │                           axis stays so adding another is one file.
│   ├── icons/              WHICH COLOUR AN ICON ROLE TAKES.
│   │   ├── colour.json
│   │   └── mono.json
│   ├── _tokens.scss        WHAT A COLOUR MEANS. Primitives mapped onto roles,
│   │                       and the one place that knows a palette and a
│   │                       density have both been imported.
│   └── _widgets.scss       The Qt stylesheet rules.
├── icons/modern/           91 Phosphor SVGs. GEOMETRY, not colour: they carry
│                           a placeholder fill and are recoloured per variant
│                           at build time.
└── scripts/
    ├── generate-config.py       palettes -> config/<palette>.json
    ├── recolour_icons.py        one icon set per palette x treatment
    └── download_phosphor_icons.py   refetch the geometry (needs network)
```

## The three axes

| Axis | Owns | Changing it affects |
| ---- | ---- | ------------------- |
| `palette` | Neutrals, chrome accent, icon ramp | The stylesheet's colours, `config/<palette>.json`, and the icon sets |
| `density` | The base spacing unit, row padding, row height | The stylesheet's geometry, nothing else |
| `icons` | Which palette variable each icon role resolves to | The icon sets, nothing else |

They are **orthogonal, and the build enforces it**: a palette fragment may not contain a length, a density fragment may not contain a colour. That is not tidiness. It is what makes spot-checking three variants sufficient evidence for twelve, because a palette then cannot move a row and a density cannot shift a hue. You can verify it yourself:

```bash
# palette axis: only colour-bearing properties should appear
diff build/qss/nebula-comfortable.qss build/qss/graphite-comfortable.qss
```

The density axis carries one value today, so there is nothing to diff across it. Add a second fragment and the same check applies: only spacing properties may differ.

## Adding a variant

**A palette.** Copy `source/palettes/_nebula.scss`, change the values, add the name to `variants.json`. Do not start from an empty file: every palette fragment must declare the same variable names, and the build compares them and names the difference if one is missing.

**A density.** Copy `source/densities/_comfortable.scss`, change the numbers, add the name to `variants.json`. Geometry only.

**An icon treatment.** Copy `source/icons/mono.json`, point each role at a different palette variable, add the name to `variants.json`. Nothing is downloaded; the existing SVGs are recoloured.

In all three cases the build will tell you if the file and `variants.json` disagree, in either direction. A fragment on disk that nobody declared is an error too, so a half-finished palette cannot become a shipped theme by accident.

## Changing a colour

Edit the palette fragment. Nothing else holds a colour.

- **Stylesheet colours** apply on the next build.
- **`config/<palette>.json`** (qBittorrent's own palette, transfer-list states, log levels, pieces bar) is regenerated by every build. It exists because QSS cannot reference a config.json colour, so the two have no choice but to be duplicated; generating one from the other is what stops them drifting.
- **Icon colours** are resolved at build time from the `$icon-` prefix. The SVGs never need re-downloading for a colour change.

Colours are not listed here on purpose. This file used to carry a status-colour table that drifted until all nine values were wrong. The palette fragments are the source of truth and they are commented.

## What a theme cannot reach

Some of qBittorrent's chrome is painted in C++ and no stylesheet touches it. Do not spend effort trying:

| Surface | Why | What is still yours |
| ------- | --- | ------------------- |
| Transfer-list progress bar | `progressbarpainter.cpp:47` forces a fusion style on Windows and macOS | Its colours, via `config/*.json` |
| Transfer-list row colours | `transferlistmodel.cpp:551` supplies `Qt::ForegroundRole` per state | The `TransferList.*` colours |
| Sidebar section captions | Font set in C++ with `setBold` + `AllUppercase`, which beats app QSS | Ground, colour, padding, radius, and the arrow's rect |
| Sidebar pane background | `TransferListFiltersWidget` has no `paintEvent` | `Palette.Base` only. Giving the sidebar a plane of its own means moving that, not writing a QSS rule |
| Status bar margins | `statusbar.cpp:156` sets a widget-level `QWidget {margin: 0}` | Padding, colour, border, radius |
| Pieces bars | Raw `QWidget::paintEvent` | The `PiecesBar.*` colours |

## A warning worth keeping

`TransferListWidget` is a `QTreeView`, and so are `CategoryFilterWidget` and `TagFilterWidget`. A rule written against the bare `QTreeView::item` selector therefore styles **both** the filter sidebar and every cell of the main torrent list.

This has already cost one release: sidebar styling written on the generic selector gave every transfer-list cell its own rounded border, which rendered as stray bracket marks at each column boundary. Scope anything sidebar-specific to the widget classes by name (`StatusFilterWidget`, `TrackersFilterWidget`, `TrackerStatusFilterWidget`, `CategoryFilterWidget`, `TagFilterWidget`), never to `QTreeView` or `QListView`.

More generally: a stylesheet that compiles is not a stylesheet that renders. There is no substitute for building a variant, loading it, and looking.
